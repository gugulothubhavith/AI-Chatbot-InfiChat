## 🚀 Quick Start

### Prerequisites

| Requirement | Minimum | Notes |
|-------------|---------|-------|
| Docker Desktop | 24+ | Must have Compose v2 |
| RAM | 8 GB | 16 GB recommended for all services |
| Disk | 10 GB free | For model weights & volumes |
| OS | Windows / macOS / Linux | All supported |

### 1 — Clone & Configure

```bash
git clone https://github.com/gugulothubhavith/Chatbot-InfiChat.git
cd Chatbot-InfiChat

# Copy the root environment template
cp .env.example .env

# Copy the backend environment template
cp backend/.env.example backend/.env
```

### 2 — Add Your API Keys

Open `.env` and fill in at least one AI provider key and the connector encryption key:

```bash
# Required: at least one AI provider
NVIDIA_API_KEY=nvapi-xxxx          # NVIDIA NIM (primary models)
GROQ_API_KEY=gsk_xxxx              # Groq (voice + fast fallback)
GOOGLE_API_KEY=AIzaSyxxxx          # Vision (Gemini)

# Required: encrypt stored OAuth tokens
# Generate: python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
CONNECTOR_ENCRYPTION_KEY=

# Optional: Stripe for subscriptions
STRIPE_SECRET_KEY=sk_live_xxxx
STRIPE_WEBHOOK_SECRET=whsec_xxxx
```

### 3 — Launch

**Windows (one-click):**
```cmd
docker-manage.bat
```
Then press **[1]** to start all services.

**All platforms:**
```bash
docker compose up -d
```

### 4 — Access

| Service | URL | Description |
|---------|-----|-------------|
| **Chat App** | http://localhost:5173 | Main user interface |
| **Admin Console** | http://localhost:5174 | Operator dashboard |
| **API Docs** | http://localhost:8000/docs | Interactive Swagger UI |
| **API Schema** | http://localhost:8000/redoc | ReDoc interface |
| **Health** | http://localhost:8000/health | Service health check |

> On first boot the backend auto-seeds an admin account. Check the logs:
> ```bash
> docker compose logs backend | grep -i "admin"
> ```

## 🛡 Security & Compliance

InfiChat was designed with security-first architecture throughout every layer.

### Authentication & Session Security
- **JWT tokens** signed with `python-jose[cryptography]` (CVE-free, pinned to 3.4.0)
- **bcrypt password hashing** with configurable cost factor
- **TOTP-based MFA** (RFC 6238) via `pyotp`
- **Refresh token rotation** with revocation on logout
- **Secure, HttpOnly, SameSite=Lax cookies** for session tokens
- **Google OAuth 2.0** sign-in + **GitHub OAuth** supported

### Transport & Network
- **TrustedHostMiddleware** — rejects requests with spoofed `Host` headers
- **CORS** — strict allowlist, no wildcard origins in production
- **Rate limiting** — SlowAPI + Redis sliding-window counters per endpoint
- **Trusted proxy chain** — `X-Forwarded-For` only accepted from RFC1918 ranges

### Data Protection
- **Fernet symmetric encryption** for stored OAuth connector tokens
- **Soft deletion** — user data is soft-deleted before hard purge (configurable retention)
- **GDPR consent recording** — all data processing consent is time-stamped and auditable
- **GeoIP routing** — jurisdiction-aware data handling

### AI Safety
- **AI Firewall** — pre-generation prompt screening
- **Safety Scanner** — post-generation output validation
- **Supervision Service** — parental controls, usage limits, timezone-aware quiet hours
- **Admin safety page** — platform-wide content policy controls

### Dependency Security
- `python-jose==3.4.0` — patched for PYSEC-2024-233
- `PyJWT==2.13.0` — patched for 7 advisories (PYSEC-2026-120/175/177/178/179, PYSEC-2025-183)
- `pip-audit` included in `requirements.txt` for CI CVE scanning

### Code Execution Sandbox
The Code Agent spawns **throwaway Docker containers** per execution run. User code never runs in the API process. The Docker socket mount trade-off is documented explicitly in `docker-compose.yml`.

## 🗃️ Database Migrations

InfiChat uses Alembic for schema migrations. **Migrations run automatically on backend startup.**

```bash
# Create a new migration after model changes
docker compose exec backend alembic revision --autogenerate -m "add_column_x"

# Apply pending migrations manually
docker compose exec backend alembic upgrade head

# Rollback one step
docker compose exec backend alembic downgrade -1

# Show history
docker compose exec backend alembic history --verbose
```

Migration files in `backend/alembic/versions/` are tracked in git and form the single source of truth for the production schema.
